# Phase 1 — UI Design Contract

> Visual and interaction contract for the Phase 1 dashboard + setup wizard. Generated by gsd-ui-researcher from CONTEXT.md (D-11..D-22, D-26), RESEARCH.md (Standard Stack), CLAUDE.md (Next.js 15.5 App Router + shadcn/ui-compatible chart libs), and the Phase 1 success criteria in ROADMAP.md.
>
> Audience: self-hosters (engineering leaders, platform engineers at 10–50 person startups) running Plausible/Langfuse/Supabase. Aesthetic anchor: minimal, dense, terminal-adjacent. Cleanliness over Datadog density.

## Spacing Scale

Tailwind defaults are the source of truth (`0, 1=4, 2=8, 3=12, 4=16, 6=24, 8=32, 12=48, 16=64`). Declared subset for this phase:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap; pill marker padding |
| sm | 8px | Compact element spacing; table row padding-y; badge padding |
| md | 16px | Default element spacing; card padding; form field gap |
| lg | 24px | Section padding; wizard step inner padding |
| xl | 32px | Layout gaps; between filter bar and chart |
| 2xl | 48px | Major section breaks; wizard step vertical rhythm |
| 3xl | 64px | Page-level top spacing on the cost dashboard |

Density rules:

- Tables: row vertical padding = 8px (sm). No extra row padding. Header row 12px top / 8px bottom.
- Cards: 16px (md) padding on small content; 24px (lg) on chart cards.
- Page max-width: `max-w-screen-2xl` (1536px) with 24px (lg) horizontal gutter on ≥`md` breakpoint, 16px (md) on mobile.

Exceptions:

- AgentSession warning modal: 32px (xl) inner padding (this dialog is intentionally larger because the copy is load-bearing).
- Touch targets for the theme toggle and "Confirm this agent" button: minimum 36px hit area (Tailwind `h-9`).

## Typography

Exactly four sizes, two weights. Inter for UI, JetBrains Mono for IDs / keys / webhook URLs / cURL commands / timestamps.

| Role | Size | Weight | Line Height | Family |
|------|------|--------|-------------|--------|
| Body | 14px | 400 (regular) | 1.5 (21px) | Inter |
| Label | 12px | 600 (semibold) | 1.4 (≈17px) | Inter — uppercase tracking-wide for filter labels and table column headers |
| Heading | 20px | 600 (semibold) | 1.3 (26px) | Inter — section headings (chart title, table title, wizard step title) |
| Display | 28px | 600 (semibold) | 1.2 (≈34px) | Inter — page title ("Cost"), wizard welcome heading |

Mono usage (same sizes as their host element — only the family changes):

- Workspace API key reveal: 14px JetBrains Mono in a `bg-muted` pill with copy button.
- Webhook URL on Done step + empty state: 14px JetBrains Mono in `bg-muted` block with copy button.
- cURL test command: 12px JetBrains Mono in `bg-muted` block with copy button. Wrap with `whitespace-pre-wrap` so long flags are readable.
- Timestamps in identity side panel and table tooltips: 12px JetBrains Mono.
- IDs (`linear_app_user_id`, session ids) in identity panel: 12px JetBrains Mono.

Caps and emphasis:

- Filter labels and table column headers: `uppercase tracking-wide` at 12px/600.
- Money values in cost table: tabular-nums (`tabular-nums` Tailwind v4 utility) so columns align.
- Never italic. Never underline except `<a>` on hover.

## Color

Single accent (blue/teal "agent identity"), single warning (amber "anomaly / synthetic data / workspace warning"), red reserved for blocking errors only. **No green** in P1 — there is no meaningful "success" state to celebrate, and the audience reads green as a generic "OK" signal that misleads.

CSS-variable-driven via shadcn `new-york` + `zinc` base; the values below are the **role bindings** the executor must wire. Tailwind classes are written in terms of roles (`bg-background`, `text-foreground`, `bg-accent`, etc.), not hex.

### Light mode

| Role | Token | Hex | Usage |
|------|-------|-----|-------|
| Dominant (60%) | `--background` | `#FFFFFF` | Page background, dashboard surface |
| Foreground | `--foreground` | `#09090B` (zinc-950) | Body text |
| Secondary (30%) | `--muted` / `--card` / `--border` | `#F4F4F5` (zinc-100) muted, `#FFFFFF` card with `#E4E4E7` (zinc-200) border | Cards, top nav, side panel, table header, code blocks |
| Muted foreground | `--muted-foreground` | `#71717A` (zinc-500) | Secondary text (filter labels, table sub-rows, "—" placeholder cells) |
| Accent (10%) | `--primary` (agent identity) | `#0EA5E9` (sky-500) | See "Accent reserved for" below |
| Accent foreground | `--primary-foreground` | `#FFFFFF` | Text on accent fills |

### Accent reserved for (explicit list — never "all interactive elements")

The `--primary` accent appears on **only** these surfaces:

1. Active nav-tab underline (Cost tab in P1; Reliability/Lineage stubs are muted).
2. Stacked-bar chart series fill (one of the 5-color agent palette derived from the accent — see "Agent palette" below).
3. Primary CTA button fill: "Continue" (each wizard step), "Confirm this agent" (identity side panel), "Try with synthetic data" (empty state).
4. Selected state on filter dropdown items.
5. Focus ring on any focusable element (`focus-visible:ring-2 focus-visible:ring-primary`).

Everything else uses `--foreground` / `--muted-foreground` / `--border`. Links inside body copy are `text-foreground underline underline-offset-4 decoration-muted-foreground hover:decoration-foreground` — **not** accent. This keeps the dashboard quiet.

### Agent palette (chart series — derived from accent so anomaly amber and error red still read against it)

Stacked-bar agent series use this fixed 5-stop palette in order of agent insertion:

1. `#0EA5E9` (sky-500 / `--primary`)
2. `#6366F1` (indigo-500)
3. `#8B5CF6` (violet-500)
4. `#14B8A6` (teal-500)
5. `#06B6D4` (cyan-500)

If >5 agents in a workspace, additional series cycle the palette with reduced saturation (`opacity: 0.7`) — the rare overflow is intentionally less prominent. Anomaly pill markers overlay in `--warning` regardless of underlying series color.

### Contrast and accessibility

- All foreground/background pairs declared above meet WCAG 2.2 AA at 14px body and 12px label (zinc-950 on white = 19.7:1; zinc-50 on zinc-950 = 18.5:1; sky-500 on white = 4.6:1 AA at 14px; amber-500 on stone-900 = 9.2:1).
- Anomaly pill markers must not rely on color alone — they include the text "↑3.2×" inside the pill so colorblind users can read the magnitude.
- Identity confidence indicator: "Unconfirmed" badge uses `border-warning text-warning bg-transparent` plus the literal word "Unconfirmed" (not just a color).
- Focus rings: `ring-2 ring-primary ring-offset-2 ring-offset-background` on all interactive elements.

## Interaction & State Contracts

### URL-stateful filters (load-bearing)

The cost dashboard reads filters from the URL on every render. State lives in `?team=ENG&cycle=2026-Q2&window=14d`. Defaults when absent: `team=All`, `cycle=All`, `window=14d`. Changing a filter calls `router.replace(newSearchParams)`; the server component re-fetches via the typed query client. Reload preserves state. Sharing a link reproduces the view exactly.

### Data fetching pattern

- Cost page is a React Server Component. Fetches happen on the server through `lib/query.ts` which calls `POST /api/v1/query` over the same origin.
- Filters are read from `searchParams` (Next.js 15 App Router pattern). No `'use client'` on the page shell.
- The chart component is `'use client'` (Recharts requires DOM); receives data as serializable props.
- The identity side panel is `'use client'` (Radix Dialog state); confirmation `POST` goes through `lib/api.ts` and triggers a `router.refresh()` to re-execute the server fetch.
- **No component reads from `pg`, `drizzle`, or any DB driver.** The CI grep `grep -r "from 'drizzle\|from 'pg" packages/web/src/` must return empty. (DASH-01, API-07.)

### Loading and error states

- Initial server render shows the chart and table skeletons (shadcn `Skeleton` components matched to chart bar shapes and table row heights). Skeletons have `aria-busy="true"`.
- API failure on the server: render an error card in the chart slot — `Could not load cost data. {short reason}. Reload the page or check the worker logs.` — and an empty table. The page itself still renders (filters, nav, banners).
- API failure on a client mutation (confirm agent, regenerate key): toast at the bottom-right per the "Generic error toast" pattern. Optimistic UI is **not** used in P1 — show a spinner inside the button, await the response, then refresh.

### Keyboard & screen-reader contract

- Top nav tabs are `role="tablist"` with arrow-key navigation. Active tab has `aria-selected="true"`.
- Filter dropdowns are Radix `Select` (built-in keyboard + ARIA).
- Side panel (Radix Dialog with `modal={false}` so the table behind remains scrollable for batch confirmation) traps focus inside the panel while open; `Escape` closes; first focus on panel open is the panel heading.
- AgentSession warning modal: `role="alertdialog"`, `modal={true}`, focus trapped, `Escape` disabled (only the click-through button exits). Screen reader announces heading + full body before button.
- API-key reveal: `Mask`/`Reveal` toggle is a `<button>` with `aria-pressed`; the masked state renders `••••••••••••••••` (16 bullet chars) so screen readers say "bullet bullet bullet" rather than reading the actual key.
- All Lucide icons used decoratively get `aria-hidden="true"`. Icons that *are* the affordance (e.g. the `copy` icon on a copy button when there's no visible text label) get `aria-label`.

### Theme

- Default to `prefers-color-scheme: system`.
- Toggle in nav cycles `system → light → dark → system`.
- Persisted in `localStorage["linearwatch-theme"]`.
- Server-side rendered with the `next-themes` `<ThemeProvider attribute="class">` pattern; suppress hydration warning on the `<html>` tag.
