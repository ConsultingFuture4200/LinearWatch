# Phase 1 Plan 01: Repo Bootstrap Summary

Bootstrapped the agentwatch monorepo: pnpm workspace with four placeholder packages
(`db`/`shared`/`server`/`web`), exact-pinned TypeScript 5.6 + Biome 1.9.4 + Vitest 2.1.5
toolchain, three-service Docker Compose stack (`postgres:16-alpine` + server + worker + web)
with multi-stage Dockerfiles, fail-fast `.env.example`, OBS-04 grep guard, and CI workflow
running lint + typecheck + test + grep gate on every push.

## What Shipped

### Workspace skeleton (Task 1)

- `pnpm-workspace.yaml` declares `packages/*`. Four packages exist with `name` matching the
  `@agentwatch/{db,shared,server,web}` interface contract from the plan's `<interfaces>`
  block.
- `tsconfig.base.json` enables `strict`, `noUncheckedIndexedAccess`, and
  `exactOptionalPropertyTypes` — non-negotiable correctness flags every package extends.
- Biome 1.9.4 covers both lint and format; configured for 100-char line width, 2-space
  indent, single quotes, semicolons, trailing commas. `noConsoleLog` and
  `noNonNullAssertion` set to `warn`.
- Vitest 2.1.5 root config discovers `packages/*/src/**/*.{test,spec}.ts` and
  `packages/*/test/**/*.{test,spec}.ts`. Performance benchmarks under `test/perf/**` are
  excluded so they don't run in the unit-test gate (D-31 benchmark goes to a dedicated CI job
  in plan 01.10).
- All dependencies exact-pinned (`grep '"\^' package.json packages/*/package.json` returns
  empty per acceptance criterion).
- Server placeholder binds `/health` on `PORT=8080` so the compose smoke test has a real
  endpoint to probe — Wave 1's Fastify rewrite replaces this.
- Worker placeholder uses `setInterval` to stay alive so Docker reports it as running until
  Graphile Worker takes over in plan 01.05.
- Web placeholder is a minimal Next.js 15 App Router page with `output: 'standalone'` so the
  Docker image stays small.

### Docker stack + CI guards (Task 2)

- `compose.yml` lists exactly four services (`postgres`, `server`, `worker`, `web`).
  `postgres:16-alpine` appears once. Zero matches for `redis`/`kafka`/`clickhouse`/
  `timescale`/`influxdb` per D-03's Postgres-only constraint.
- Both Dockerfiles use `FROM node:22-alpine` and `corepack prepare pnpm@9.12.0 --activate` so
  the runtime version is locked to the same pnpm the host CI uses.
- `Dockerfile.worker` is shared between `server` and `worker` services — same compiled tree,
  different `command:` entrypoints. This is the build-once-deploy-twice pattern; it cuts
  total image build time roughly in half versus separate Dockerfiles.
- `Dockerfile.web` uses Next.js standalone output so the runtime stage only copies
  `.next/standalone` + `.next/static` + `public` — no `node_modules` required at runtime.
- `.env.example` is the fail-fast contract surface (DEPLOY-03). Required vars:
  `DATABASE_URL`, `LINEAR_CLIENT_ID`, `LINEAR_CLIENT_SECRET`, `LINEAR_WEBHOOK_SECRET`. Set
  after wizard: `WORKSPACE_ID`, `AGENTWATCH_INTERNAL_API_KEY`. Tunables with defaults:
  `IDENTITY_CONFIDENCE_THRESHOLD=0.8`, `LOG_LEVEL=info`, `TELEMETRY_OPT_IN=false`.
- `scripts/check-no-req-body.sh` greps `packages/{server,web,shared}/src/` for
  `req.body|request.body` excluding `rawBody`. Pitfall 12 mitigation: `LOG_LEVEL=debug`
  cannot leak payloads if the production code never reads `req.body`. Hardened to
  short-circuit with success when no source dirs exist yet (early-phase resilience —
  packages add `src/` content as later plans land).
- `scripts/smoke-compose.sh` injects synthetic env vars (`smoke-client`, etc.) so the
  fail-fast checks pass, runs `docker compose up --build -d`, and polls `:3000` and
  `:8080/health` with a 300s budget. DEPLOY-01 enforcement.
- `.github/workflows/ci.yml` runs `pnpm install --frozen-lockfile`, then lint, typecheck,
  test, and the grep gate. Compose smoke and the webhook ack benchmark are deferred to
  separate jobs added in plans 01.10 and 04.x respectively.
- `README.md` documents the two production-relevant deployment notes: reverse-proxy auth
  (nginx + Caddy snippets, ≤15 lines each, with explicit "exclude webhook paths from basic
  auth" warning) and PgBouncer transaction-mode (`?pgbouncer=true` flag, ≥1.21 requirement
  per Pitfall 11). Linear Business/Enterprise plan note is in its own subsection.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking issue] Biome lint failed on `.planning/config.json`**

- **Found during:** Task 1 verification (`pnpm lint`)
- **Issue:** Biome's default scan included `.planning/` (GSD planning artifacts) and flagged
  `.planning/config.json` for missing trailing newline. The GSD tooling owns that file's
  format; it is not source code.
- **Fix:** Added `.planning/**`, `PRD_v0.1.0.md`, `README_v1.md` to `biome.json`'s
  `files.ignore` list. Biome now only scans actual source.
- **Files modified:** `biome.json`
- **Commit:** included in 99c6dc7

**2. [Rule 3 — Blocking issue] `check-no-req-body.sh` failed when `packages/web/src` doesn't exist**

- **Found during:** Task 2 verification (script exit code)
- **Issue:** The bash script's `grep -r` errored when one of the listed source directories
  didn't exist (Wave 0 hasn't created `packages/web/src/` yet — the web placeholder lives in
  `packages/web/app/` per Next.js App Router convention).
- **Fix:** Script now checks each candidate dir and only includes the ones that exist.
  When zero dirs exist, exits with `OK: no production source dirs to scan yet`. Future
  plans that add `src/` directories light up the gate automatically.
- **Files modified:** `scripts/check-no-req-body.sh`
- **Commit:** included in 59c38ba

**3. [Rule 3 — Blocking issue] README literal-string check expected lowercase `reverse-proxy`**

- **Found during:** Task 2 acceptance criteria verification
- **Issue:** Acceptance criterion required literal string `reverse-proxy` (lowercase). README
  initially had only `Reverse-proxy` (heading) and `reverse proxy` (prose).
- **Fix:** Changed prose to `reverse-proxy` (hyphenated, lowercase).
- **Files modified:** `README.md`
- **Commit:** included in 59c38ba

### Architectural Choices Within Plan Scope

- **Biome over eslint+prettier:** CONTEXT.md explicitly delegates "Linting/formatting" to
  Claude's discretion ("if Biome handles both, use it. Otherwise eslint + prettier. Don't
  bikeshed."). Biome covers both; chosen.
- **Web placeholder uses `app/` not `src/`:** Next.js 15 App Router convention places routes
  at `app/page.tsx` (or `src/app/page.tsx` if a `src` dir exists). The placeholder uses the
  flat layout because it adds zero ceremony in Wave 0; Wave 3 may move to `src/app/` if the
  dashboard grows enough to warrant it.
