# Phase 1 Plan 03: Shared Package Summary

Privacy contract and query/SDK validation contract for the linearwatch
monorepo. `hashTitle()` is now the sole chokepoint for raw-title reads
(D-26 / D-27 / Pitfall 4 / Pitfall 13), and the query API + SDK event
boundaries are guarded by closed Zod enums and a discriminated union
respectively. Both contracts are enforced at compile time first, runtime
second.

## What Shipped

### Privacy primitive (Task 1)

`packages/shared/src/privacy.ts`:

- `TitleHash = string & { readonly __brand: 'TitleHash' }` — branded string
  type. The only way to obtain a `TitleHash` value is `hashTitle()`.
  Drizzle's `issues.title_hash` column is typed via
  `customType<{ data: TitleHash }>` (in `@linearwatch/db`), so a stray
  `{ titleHash: 'raw' }` insert is a TypeScript compile error.
- `hashTitle(rawTitle, workspaceSalt)` —
  `sha256(salt + ":" + raw.trim().toLowerCase()).digest('hex')`. Per-workspace
  salt prevents cross-workspace lookup attacks if hashes ever leak to the
  hosted aggregator (D-27).
- 7 vitest cases:
  1. 64-char hex output (sha256)
  2. Case normalization (`Foo` ≡ `foo` ≡ `FOO`)
  3. Whitespace normalization (`  bar  ` ≡ `bar`, `\tbar\n` ≡ `bar`)
  4. Salt differentiates (`hashTitle('x', 'a') !== hashTitle('x', 'b')`)
  5. Different inputs differ
  6. Empty input is hashable and deterministic
  7. `@ts-expect-error` on `const _bad: TitleHash = 'plain-string'` confirms
     the brand at compile time

### Query API + SDK event schemas (Task 2)

`packages/shared/src/query.ts`:

- `MetricName = z.enum(['cost_by_agent', 'agent_session_count'])` — closed
  enum (API-02 / API-04). Adding a metric is a one-line change here +
  registering a static SQL function in `packages/server/src/query/metrics/`.
- `DimensionName = z.enum(['agent', 'team', 'cycle'])` — closed enum
  (API-05). `repo` and `model_tier` deferred to P2.
- `Filter = { field, op, value }` with `FilterField` and `FilterOp`
  themselves closed enums.
- `Window` is a `.refine()`d object: must have `last: '14d'|'168h'|...` OR
  both `from` and `to` (ISO datetimes). The refine message is part of the
  contract — the API responds with the Zod error directly.
- `QueryRequest = { metric, dimension?, filters?, window }`.
- `QueryRow = { key, value, count?, bucket_at? }` and `QueryResponse =
  { metric, dimension?, window, rows }` for the response envelope.

`packages/shared/src/events.ts`:

- `SessionStartEvent`, `SessionEndEvent`, `CostRecordedEvent` Zod schemas
  share a `Common` set: `session_id`, `occurred_at`, optional
  `idempotency_key` (max 128 chars per D-10).
- `SdkEventBody = z.discriminatedUnion('event_type', [...])`.
- `cost_usd` is `z.number().nonnegative()`; `tokens_in`/`tokens_out` are
  `z.number().int().nonnegative().optional()` — non-int floats reject.

`packages/shared/test/query.test.ts` runs 19 cases:

- 3 for `MetricName` (accept P1, reject `arbitrary_sql_injection` and
  `revert_rate`, `.options` exact-match)
- 3 for `DimensionName` (accept P1, reject `repo`/`model_tier`,
  `.options` exact-match)
- 6 for `QueryRequest` (minimal, full, absolute window, missing window,
  empty window, malformed `last`)
- 7 for `SdkEventBody` (each event type, idempotency_key passthrough,
  unknown event_type, negative `cost_usd`, non-int `tokens_in`)

## Pitfalls Mitigated

- **Pitfall 4 / 13 (Title hashing missed / title leakage):** the privacy
  contract is now load-bearing and compile-time-enforced. `hashTitle()` is
  the sole producer of `TitleHash`; `issues.titleHash` (in
  `@linearwatch/db`) is typed `TitleHash`; assigning a plain string is a
  TypeScript error before the test suite runs. The `@ts-expect-error`
  case in `privacy.test.ts` is the second line of defense; the OBS-04
  grep guard from 01.01 is the third.
- **Anti-feature: custom SQL in rule engine** (PITFALLS.md): `MetricName`
  and `DimensionName` are closed Zod enums. The query API dispatcher (Plan
  01.06) WILL map enum values to static SQL functions — no string
  concatenation, no `eval`-equivalent path. The runtime `parse()` throw is
  the gate that prevents an attacker-controlled `metric: "DROP TABLE..."`
  from reaching the SQL layer at all.

  check.

  value imports under Biome's organize-imports rule.
- **Fix:** Reordered the named imports.
- **Files modified:** `packages/shared/test/privacy.test.ts`

### Architectural Choices Within Plan Scope

- **Re-export ordering in `index.ts`:** `privacy → query → events` is
  alphabetical-ish but actually follows the dependency-criticality order
  (privacy is load-bearing across the codebase; query is the API contract;
  events is the SDK contract). Future packages added here should respect
  the same gradient.
- **`SessionStartEvent.agent_name` is `z.string().min(1)`, not an enum:**
  the plan said free-text, resolver maps to `agent_id`. An enum here would
  fight the resolver's job. Same goes for `vendor` (optional free text in
  P1; closed enum once vendor enrichment lands in P2).
- **Added `.options` exact-match assertions for `MetricName` and
  `DimensionName`:** the plan's acceptance criteria say enum values
  EXACTLY match a list — using `.options` instead of just "happy path"
  parsing makes the assertion explicit and makes future drift visible in
  the diff.
- **`tokens_in`/`tokens_out` are non-negative ints, not just non-negative
  numbers:** the plan reference snippet had `.int()` and I kept it because
  fractional tokens are a category error from any vendor we'd ingest.
  Test 7 of `SdkEventBody` exercises it explicitly.


  `SdkEventBody.parse(req.body)` and switches on `result.event_type` —
  TypeScript's discriminated-union narrowing makes per-branch field
  access type-safe.

real implementation, so `packages/db/src/schema/issues.ts` continues to
