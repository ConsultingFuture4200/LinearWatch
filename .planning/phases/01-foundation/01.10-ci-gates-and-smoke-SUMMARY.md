Comment-aware skip pattern (lines starting with `*` or `//`) prevents false positives on
JSDoc references to forbidden patterns — the schema file's `// NO 'title: text(...)' field`
comment was a near-trip until the skip rule was added.

### Runtime tests (Task 1 — commit `1308c30`)

`packages/server/test/integration/privacy-guard.test.ts`:

1. Spins up its own Postgres database (`agentwatch_priv`), runs Drizzle + Graphile migrations.
2. Seeds workspace, team, cycle, agent, 5 sessions, 1 issue (with a hashed title carrying
   the seed payload's hash).
3. Generates a per-run unique seed: `__SEED_DETECTOR_PHASE1_<32 hex chars>__`.
4. POSTs that payload through the real `/webhooks/linear` route (HMAC-signed, real
   `Linear-Delivery` UUID).
5. Drains `resolve_identity` via `runOnce` so `identity_mappings` is populated end-to-end.
6. Iterates 8 permutations (2 metrics × 4 dimension settings) against `/api/v1/query` and
   asserts the seed string appears in zero responses.

`packages/server/test/integration/no-title-column.test.ts`:

1. Fresh database; runs Drizzle migrations.
2. `SELECT column_name FROM information_schema.columns WHERE table_name='issues'`.
3. Asserts `title_hash` IN, `title` NOT IN.

Both tests follow the project's `app.inject` pattern (matches `idempotency.test.ts`,
`query-api.test.ts`, `sdk-event.test.ts`) and self-skip when Postgres is unreachable.

### CI workflow (Task 2 — commit `fc4dcd2`)

Six independent jobs in `.github/workflows/ci.yml`:

```
┌─────────────────────────────────────────────────────────────────┐
│  Push or PR                                                     │
├─────────────────────────────────────────────────────────────────┤
│  static-checks         (no DB; ~30s)                            │
│  lint-typecheck-test   (Postgres; runs `pnpm test`)             │
│  bench-webhook-ack     (Postgres; D-31 p99 200ms gate)          │
│  e2e-setup-wizard      (Postgres + Playwright + chromium)       │
│  privacy-guard         (Postgres; seed trace + schema check)    │
│  compose-smoke         (Docker; full stack boot ≤300s)          │
└─────────────────────────────────────────────────────────────────┘
```

`lint-typecheck-test` was reorganised in this plan: the original (plan 01.01) ran `pnpm test`
without first building the workspace packages. Vitest resolves intra-workspace imports
(e.g. `@agentwatch/db` from `@agentwatch/server`) via `package.json#main`, which points at
the built `dist/`. Plans 01.04+ added integration tests that import sibling packages — they
silently failed in CI prior to this plan because no build step preceded `pnpm test`. Fixed
by inserting the four `pnpm --filter ... build` steps before the test step.

## How to Read a Failing Gate

| Failing gate | Most likely root cause | First file to check |
|--------------|------------------------|---------------------|
| `static-checks` (req.body) | A handler logged or read `req.body` without `rawBody` / annotation | `packages/server/src/routes/**` (recent diff) |
| `static-checks` (title-leak) | Migration or schema added a `title text` column on issues | `packages/db/src/schema/issues.ts`, `packages/db/migrations/*.sql` |
| `static-checks` (web-no-db-import) | Dashboard imported `pg` or `drizzle-orm` directly | `packages/web/src/**` (recent diff); use `fetch` against the query API instead |
| `lint-typecheck-test` | TypeScript error or test regression | `pnpm typecheck`, `pnpm test` locally |
| `bench-webhook-ack` | Webhook handler regressed past 200ms p99 (D-31) | `packages/server/src/routes/webhooks/linear.ts`; usually a synchronous DB call snuck in |
| `e2e-setup-wizard` | AgentSession warning copy paraphrased or click-through removed | `packages/web/src/components/agentsession-warning-modal.tsx` |
| `privacy-guard` | A query-API metric/dimension serialiser leaked a raw title | `packages/server/src/routes/api/v1/query.ts`; usually a JOIN that pulled a `title` column that shouldn't exist |
| `compose-smoke` | Docker stack stopped booting in 5 minutes | `compose.yml`, `Dockerfile.*`, `scripts/smoke-compose.sh` output |

## Pitfalls Mitigated

- **Pitfall 4 / 13 (title leakage):** `privacy-guard` runtime test seeds a unique detector
  string through the real ingest path and iterates every (metric, dimension) permutation.
  `check-no-title-leak.sh` blocks the schema regression at the static layer. Both gates
  have to pass on every push.
- **Pitfall 12 (`req.body` log leak):** `static-checks` runs `check-no-req-body.sh` on every
  push (carried forward from plan 01.01).
- **Pitfall 8 (idempotent migrations):** `lint-typecheck-test` runs the full Phase-1 test
  suite which includes `migrations-on-startup.test.ts` (plan 01.04) — a migration that
  re-applies non-idempotently turns into a red build before the related plan ever lands.
- **Pitfall 14 (schema drift):** `migrations-on-startup.test.ts` and the new
  `no-title-column.test.ts` both run on the live Postgres in CI; `migrate(...)` is the
  blocking step before the listener binds in production (plan 01.04), and CI proves the
  contract holds end-to-end.

## Deviations from Plan

### Architectural choices within scope

**Privacy-guard test uses `app.inject`, not subprocess spawn.** The plan's literal test
called `spawn('node', ['packages/server/dist/index.js'])`. Switched to Fastify's
`app.inject` for two reasons:

1. The threat surface — title strings appearing in any *route-handler* response — is
   exercised identically by injection. The network layer cannot reintroduce a title leak;
   it can only fail to expose one already present.
2. Reliability — the spawn approach requires a `dist/` build inside the test setup and
   port binding, which is fragile and slow. Every other Phase-1 integration test uses
   `app.inject`; matching the codebase pattern (CLAUDE.md rule 5) is the smaller surface.

The plan's `<verify>` command explicitly prefixes the test invocation with
`pnpm --filter @agentwatch/server build &&` — that step is still useful for verifying the
production build never breaks, and CI runs it in `lint-typecheck-test` anyway. Locally the
test does not need it.

**Static title-leak grep skips comments.** The schema file's
`// NO 'title: text('title')' field anywhere — title_hash is the only title surface.`
comment trips the naive regex. Skipped JSDoc `*` and line `//` comments. The runtime
no-title-column test (`information_schema`) is the source of truth; the static check is
the fast feedback layer.
